# Monetisation and Amazon verification

The one-time ENTITLED product is `com.lifetalea.premium`. The owner approved GBP4.99 in the UK and Amazon-calculated prices elsewhere. Those prices are saved, and the IAP is Approved in Amazon’s TEST channel. Public promotion remains gated on completed transaction and release testing.

Free/Premium boundaries remain: ordinary local stories/photos/timeline, three albums, short recordings, scrapbook drafts and basic backup are free. Premium gates additional albums, longer recordings, PDF export and encrypted backup creation. No permanent cloud transcription benefit is promised.

Server RVS and the Android signed-entitlement client are now implemented locally. See [verifier setup and limitations](../server/receipt-verifier/README.md). The private Amazon shared secret remains on the server. The app pins a separate RSA public key, verifies the server signature, user/receipt/SKU/environment/time binding and active status, and acknowledges fulfillment only after verification. Existing cached Premium booleans are ignored. Signed cache requires current SDK user identity, monotonic expiry and the same boot counter; post-reboot/offline behavior remains a live-test gate.

The Amazon public AppstoreAuthenticationKey.pem is bundled. The app now also declares package visibility for Amazon Appstore and App Tester, needed on newer Android versions. Server endpoint/signing public key are deliberately empty in the default build, and initiating purchases is disabled. The public purchase switch cannot bypass signature/RVS verification. The Supabase verifier is deployed with private credentials and trusted HTTPS. The separate LAT candidate has its public URL/pin; standard release purchases stay off until LAT and public-release gates pass.

Core contract tests use fictional Amazon responses and ephemeral signing keys. Additional real App Tester sandbox SDK/RVS tests passed after a cancellation fix, and the deployed production verifier passed a synthetic invalid-receipt smoke. They prove local contract, failure and signature behavior; they do not establish live Amazon purchases or LAT approval. Complete purchase, pending/failure, refund, restore, account-switch, interruption and offline scenarios on configured Amazon channels. Independent security/privacy review and final legal disclosures remain pending.
