# Monetisation and Amazon verification

The model remains a one-time ENTITLED product, `com.lifetalea.premium`, with marketplace prices pending publisher approval. The earlier GBP 4.99 figure is a hypothesis, not an approved/configured price. The last read-only console inspection found zero in-app items; no products, prices or account settings were changed during local implementation.

Free/Premium boundaries remain: ordinary local stories/photos/timeline, three albums, short recordings, scrapbook drafts and basic backup are free. Premium gates additional albums, longer recordings, PDF export and encrypted backup creation. No permanent cloud transcription benefit is promised.

Server RVS and the Android signed-entitlement client are now implemented locally. See [verifier setup and limitations](../server/receipt-verifier/README.md). The private Amazon shared secret remains on the server. The app pins a separate RSA public key, verifies the server signature, user/receipt/SKU/environment/time binding and active status, and acknowledges fulfillment only after verification. Existing cached Premium booleans are ignored. Signed cache requires current SDK user identity, monotonic expiry and the same boot counter; post-reboot/offline behavior remains a live-test gate.

The Amazon public AppstoreAuthenticationKey.pem is bundled. The app now also declares package visibility for Amazon Appstore and App Tester, needed on newer Android versions. Server endpoint/signing public key are deliberately empty in the default build, and initiating purchases is disabled. The public purchase switch cannot bypass signature/RVS verification. The server service, private credentials, trusted HTTPS host, pinned public key, ENTITLED product/prices and configured Amazon tests are still required before enabling a production flow.

Tests use fictional Amazon responses and ephemeral signing keys. They prove local contract, failure and signature behavior; they do not establish live Amazon purchases or LAT approval. Complete purchase, pending/failure, refund, restore, account-switch, interruption and offline scenarios on configured Amazon channels. Independent security/privacy review and final legal disclosures remain pending.
