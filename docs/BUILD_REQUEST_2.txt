## Sections 24–31: SEO, Execution, Deliverables & Acceptance Criteria

# 24. AI SEARCH OPTIMISATION (AEO / GEO)

Build a premium, multilingual, search-engine-accessible marketing website for LifeTalea.

The website must accurately communicate the product's features, privacy protections, supported devices, voice capabilities, and available languages.

Optimise for traditional search engines and AI-assisted discovery, including search experiences that retrieve and summarise publicly accessible web content.

Do not promise search rankings, AI citations, recommendations, or guaranteed visibility.

## 24.1 Website architecture

Use Next.js with TypeScript, responsive layouts, and accessible components.

Create these pages:

1. Home
2. Features
3. Family Memory Journal
4. Voice Story Recording
5. Voice Transcription
6. Digital Scrapbook
7. Family Timeline
8. Keepsake Books
9. Offline Memory Journal
10. Fire Tablet Compatibility
11. Languages
12. Pricing
13. Frequently Asked Questions
14. Privacy Policy
15. Support
16. Contact

Include a clear download link to the official Amazon Appstore listing once the application is published.

Do not invent a live Appstore URL.

## 24.2 Search-intent content

Create genuinely useful content answering questions such as:

- How can I preserve family memories digitally?
- What is a good family memory journal app?
- Can I record family stories on a Fire tablet?
- How do I turn family memories into a book?
- Can I create a private digital scrapbook?
- How do I organise old family photographs?
- Can I record my parents' life stories?
- What is the best way to preserve grandparents' memories?
- Can I save voice recordings and photographs together?
- Can I use a family memory journal without internet?
- How do I create a printable family keepsake book?
- Can I transcribe family voice recordings?

Use clear, natural language.

Provide practical examples.

Only describe features that have actually been implemented.

Avoid thin, repetitive, automatically generated pages.

## 24.3 Technical SEO

Implement:

- Server-rendered or statically generated crawlable HTML
- Unique page titles
- Descriptive meta descriptions
- Clear heading hierarchy
- Canonical URLs
- XML sitemap
- Robots.txt
- Appropriate hreflang annotations
- Open Graph metadata
- Social sharing previews
- Responsive layouts
- Accessible navigation
- Optimised images
- Internal linking
- Fast page loading
- Structured data

Use appropriate Schema.org types where relevant:

- SoftwareApplication
- MobileApplication
- Organization
- WebSite
- BreadcrumbList

Use FAQPage markup only where appropriate and consistent with current search-engine guidance.

Structured data must accurately match visible page content.

Never fabricate ratings, reviews, awards, download counts, or testimonials.

## 24.4 AI search readiness

Make important product information available as crawlable HTML text.

Clearly identify:

- Product name
- Developer or publisher
- App purpose
- Supported platforms
- Main features
- Offline capabilities
- Privacy model
- Voice functionality
- Supported languages
- Pricing model
- Support contact
- Official download location

Provide concise, accurate answers to common user questions.

Maintain consistent product facts across the website, Amazon listing, support pages, and structured data.

Do not create speculative metadata or claim that special AI optimisation techniques guarantee recommendations.

## 24.5 Worldwide website localisation

Localise website content for every approved website locale.

Use locale-specific URLs where appropriate.

Translate:

- Navigation
- Headings
- Feature descriptions
- FAQ answers
- Calls to action
- Pricing explanations
- Privacy summaries
- Support content
- SEO metadata
- Structured-data text fields

Use appropriate hreflang relationships.

Do not automatically publish unreviewed machine translations.

Maintain a localisation status report.

## 24.6 Website acceptance criteria

The website is complete only when:

- Every required page exists.
- Production build succeeds.
- Navigation works.
- Metadata is generated correctly.
- Sitemap and robots.txt are valid.
- Structured data passes available validation.
- Approved translations are complete.
- Locale switching works.
- No fabricated product claims exist.
- Broken links are identified and resolved.
- Privacy and support pages are accessible.

Do not claim deployment unless a real deployment has succeeded.

# 25. CONCRETE AUTONOMOUS CODEX EXECUTION WORKFLOW

## Primary execution mandate

You are responsible for implementing LifeTalea, not merely planning it.

Execute development tasks in the repository.

For each phase:

1. Inspect existing code.
2. Implement the required functionality.
3. Run relevant build commands.
4. Execute available tests.
5. Identify failures.
6. Fix defects.
7. Rerun tests.
8. Update documentation.
9. Record evidence.
10. Continue to the next phase.

Do not stop after creating a README or development plan.

Preserve existing files and Git history.

Never overwrite unrelated work.

Inspect:

- Repository structure
- Git status
- Java installation
- Android SDK
- Kotlin toolchain
- Gradle

# 28. MANDATORY ACCEPTANCE CRITERIA

Use PASS, FAIL, BLOCKED, and NOT TESTED statuses.

Never treat BLOCKED or NOT TESTED as PASS.

## AC-01 — Android build

- Debug build succeeds.
- Release build succeeds when signing and build configuration permit.
- No critical compilation errors remain.
- Required project files exist.
- No secrets are embedded in the application.

## AC-02 — Memory management

- Users can create, edit, delete, and retrieve memories.
- Records survive application restart.
- Album relationships remain valid.
- Search returns appropriate results.
- Database migrations preserve data.

## AC-03 — Audio recording

- Recording starts successfully.
- Pause and resume work.
- Recordings can be stopped and saved.
- Saved recordings play correctly.
